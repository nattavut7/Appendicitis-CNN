# R2 Methods-to-Code and Reviewer Mapping

This document separates:

- **R1-reported**: statements in the previously submitted manuscript, not independently verified.
- **R2-implemented**: working reproducibility features of this repository.
- **Not established**: requires original experiment logs, CT data, weights, ethics/permissions, annotations or new experiments.

| R1/R2 topic | Implementation | Evidence/limitation |
|---|---|---|
| R1 Table 1: 0.58M, 2 groups, 5×5 kernel, width=0.75 | `appendicitis_r2/model.py`, `configs/r2.yaml` | Exactly 579,619 trainable parameters for this **reference network**. Per-layer channel allocations are new and may differ from R1 implementation. Existing original GitHub network was a materially different small CNN. |
| R1 Section 4.1: 1,650 cases, patient-level splits | `data.py`, `main.py audit/split` | No patient data included. Validation guards leakage. Patient counts require original manifest. |
| R1 Table 3: 1,100 train, 220 val, 330 test | `data.py` | Actual split counts are calculated, never hardcoded; different patient-per-image multiplicity may yield different image counts. |
| R1 Figure 9: 1,650 classified examples vs test 330 | `metrics.py` | Fix requires **original individual predictions**. R2 uses test-only patient-level confusion matrix and records source. |
| R1 Section 4.2: HU window, ROI, spacing, optional histogram | `data.py`, config | DICOM HU window is mandatory explicit config; actual R1 clipping, ROI, histogram and physical resampling **unverified**. |
| R1 Table 2: flips, elastic, affine, brightness, contrast, noise, CutMix, MixUp | `augmentation.py` | All implemented and configurable. Whether ALL were used for the original results is **unverified**. Augmentation plausibility requires expert audit. |
| R1 Table 8: selected rotation/crop/noise ablation | `scripts/run_ablation.py --mode selected` | Correctly labeled **selected** rather than comprehensive. Numbers will be from actual experiments, not copied from R1. |
| Reviewer 6 #3: complete component ablation | `scripts/run_ablation.py --mode full` | One-component-out on full configuration; statistical per-run comparisons are possible after training. Large compute cost. |
| R1 Section 3.3: curriculum stages | `engine.py` | Requires verified difficulty label per case; stage fractions configurable. Comparison with random order via `train.curriculum:false` in matched experiment. |
| R1 Section 3.5: MC dropout T=20 | `engine.py` | Dropout activated at inference while BN remains in eval, variance and mean output exported. |
| Reviewer 6 #6: calibration | `metrics.py` | Empirical ECE/Brier/reliability, referral threshold from validation and risk–coverage evaluation; not a clinically validated threshold. |
| Reviewer 6 #7: fair baselines | `scripts/run_baselines.py` | Shared config and seeds; model-specific tuning fairness still requires a prespecified equal search budget. |
| Reviewer 6 #9: edge and quantization | `benchmark.py` | Measures actual hardware; dynamic quant of linear layers only. Pruning/QAT **not claimed implemented**. No clinical edge device is certified. |
| Reviewer 6 #10: Grad-CAM | `interpretability.py` | Qualitative. No radiologist region annotation metric or reader study included. |
| Reviewer 6 #11: statistics | `metrics.py`, `statistics.py` | Patient-level bootstrap percentile CI, paired model-swap permutation tests and Holm correction on actual predictions. Original manuscript p-values cannot be reconstructed without records. |
| Reviewer 6 #12: demographic fairness | `metrics.py` | Descriptive subgroup estimates if metadata is present; small groups must be interpreted cautiously. Does not prove fairness. |
| Reviewer 6 #13: clinical integration | Not a deployment product | Human oversight and regulatory authorization needed before clinical use. |
| Reviewer 6 #14: physics/PDE | Not implemented | Research discussion only: no thermodynamic or PDE-based modeling in this image classifier. |

## Required before asserting numerical equivalence with R1

1. Original patient-level manifest and partition hashes, image preprocessing/CT HU and ROI parameters.
2. Original training scripts, all experiment random seeds, checkpoints and logs.
3. Raw held-out patient predictions and actual ROC/confusion matrix, especially because R1 Figure 9 and Table 3 differ.
4. Test-set access/permissions and an appropriate evaluation protocol.
5. Pruning/QAT checkpoint variants and hardware measurement data, if those claims remain in manuscript.
6. Full ablation runs for any techniques claimed to have been experimentally ablated.

Do not publish synthetic fixture metrics as clinical results. Do not imply CI generated by repeated seeds is the same as a patient bootstrap CI. Document whether every row represents an image, a series, or an individual patient.
